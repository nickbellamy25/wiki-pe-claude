A reusable function project is the toolkit layer from the [two-layer system](/projects/two-layer-system). Build it once and it pays you back on every opportunity that follows: the fiftieth market assessment comes out in the same disciplined shape as the first, without you re-typing your method each time. This page walks through standing one up, using **Market Assessment** as the worked example: the project you will open to run a market assessment for any new target.

The key thing to hold in mind: this project holds *how you assess a market*, not any one target's data. It is generic, evergreen, and safe to share across the team.

## Building the Market Assessment project

<Steps>
  <Step title="Create a new project">
    In the left menu, open <strong>Projects</strong> and choose <strong>New project</strong>. This gives you an empty workspace with two parts to fill: the custom instructions and the knowledge base.
  </Step>
  <Step title="Name it for the function, not a target">
    Call it <strong>Market Assessment</strong> (or "Commercial Assessment"). The name should describe the repeatable task, because you will use it across many different targets. Avoid any opportunity-specific name: this project is permanent and shared.
  </Step>
  <Step title="Write the custom instructions">
    This is where the methodology lives. Set the role (a [Firm Name] strategy consultant running a market assessment for a client), the scope (work only from the attached documents for the target in question), and the output format (the headings and structure you want every assessment to follow). The template below is a ready-to-paste starting point.
  </Step>
  <Step title="Add evergreen knowledge">
    Upload the reference material that applies to every assessment, never a single target. Good candidates: your assessment framework, your standard client questions, and a sample report structure that shows Claude the shape of a finished output. These files teach Claude your house style once, for good.
  </Step>
  <Step title="Use it across targets">
    From now on, to assess a new target you open the Market Assessment project, start a chat, and attach just that one target's management presentation or data pack. The methodology and templates are already loaded, so you get a consistent assessment every time without re-explaining how your team works.
  </Step>
</Steps>

Notice what is *not* in the knowledge base: no management presentation, no financial model, nothing tied to a live opportunity. The only opportunity-specific file enters later, attached to an individual chat, and even then the assessment itself is generic enough that this remains a clean, shareable toolkit.

## The custom instructions to start with

Paste this into the project's custom instructions and adapt the headings and criteria to match your team's house style.

<PromptCard title="Custom instructions for a Market Assessment project">
You are a [Firm Name] strategy consultant running a market assessment on a target for a private equity client. In each chat I will attach one target's documents (a management presentation, data pack, or vendor due diligence report). Work only from those attached documents plus the frameworks in this project's knowledge.

For every target, produce the assessment using these headings:
1. Business overview: what they do and how they make money
2. Financial highlights: revenue, EBITDA, growth, margins (in a table, with year-over-year change)
3. Market position: size, growth, and where the target sits among competitors
4. Fit against client questions: address each question in Client_key_questions, with a one-line reason
5. Key risks and open questions
6. First three questions to ask management

Rules:
- Cite the source document (and page if visible) for every figure you report.
- Flag clearly anything the document is vague about, omits, or that looks unusual.
- Do not invent figures. If a number is not in the document, say so rather than estimating.
- Keep it concise and skimmable. This is an assessment, not a full diligence report.
</PromptCard>

<Callout type="tip" title="Refine the project, not just the chat">
When an assessment comes back slightly off (a heading you did not want, a level of detail that misses), do not just correct it in the chat. Update the project's custom instructions so the fix sticks for every future target. A function project improves over time: each adjustment you bank makes the next dozen assessments better.
</Callout>

## Other function projects worth building

Market assessment is the obvious first one, but the same recipe builds any reusable toolkit. A **Market Research** project holding your research framework and output format. A **Diligence Report** project holding your report template and tone. Each follows the identical pattern: name it for the task, write the methodology into the instructions, add evergreen templates, keep all opportunity-specific data out.

For ready-made starting points across several of these, see the [Instruction templates](/projects/templates) library. With the toolkit layer built, the next step is the workbench: [Setting up a deal project](/projects/deal-setup) for one live opportunity.
